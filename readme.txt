# Лабораторная работа №4: Механизм Proof-of-Work в распределенном блокчейне

## Цель работы
Изучить и реализовать механизм консенсуса Proof-of-Work (PoW) в распределенной блокчейн-системе на Python. Сравнить поведение сети с базовым консенсусом «первый прислал — тот и прав».

## Описание проекта
Проект представляет собой симуляцию P2P-сети из трех узлов (Node). Каждый узел хранит собственную копию блокчейна. Для добавления нового блока узел обязан выполнить вычислительную работу — найти такое значение `nonce`, при котором SHA-256 хеш блока начинается с заданного количества нулей.

## Этапы реализации

### Шаг 1. Модификация класса Block
- В класс `Block` добавлено поле `nonce` (целое число).
- Метод `calculate_hash()` обновлен: `nonce` включен в процесс хеширования. Это гарантирует, что изменение `nonce` полностью меняет итоговый хеш.

### Шаг 2. Реализация метода mine_block
- В класс `Block` добавлен метод `mine_block(difficulty)`.
- Метод осуществляет перебор значений `nonce` (от 0 и далее), пока хеш блока не начнет соответствовать условию `hash.startswith('0' * difficulty)`.
- Выводит время майнинга и количество затраченных попыток.

### Шаг 3. Обновление класса Blockchain
- В класс `Blockchain` добавлено поле `difficulty` (по умолчанию 4).
- Генезис-блок также проходит процедуру майнинга при инициализации цепочки.
- Метод `add_block()` переписан: теперь блок добавляется в цепочку только после успешного вызова `mine_block()`.
- Метод `is_valid()` проверяет не только целостность хешей и связей, но и соответствие каждого блока уровню сложности (PoW).

### Шаг 4. Модификация класса Node
- Логика создания блока вынесена в метод `create_and_broadcast_block()`: узел сначала майнит блок локально, и только затем рассылает его соседям.
- В методе `receive_block()` добавлена проверка PoW: узел принимает входящий блок только в том случае, если его хеш удовлетворяет текущему уровню сложности.

### Шаг 5. Моделирование одновременного майнинга
- Создаются 3 узла, соединенные в полный граф.
- Задается сложность `difficulty = 4`.
- Два узла (Node_1 и Node_2) одновременно пытаются смайнить блок с индексом 1.
- Блок, который был смайнен и доставлен первым, принимается всей сетью. Второй блок отклоняется, так как ячейка с данным индексом уже занята.

### Шаг 6. Проверка защиты от подделки
- Данные в уже смайненном блоке искусственно изменяются.
- Метод `is_valid()` возвращает `False`, так как пересчитанный хеш не совпадает с сохраненным.
- При попытке пересчитать хеш без майнинга, валидация также не проходит: новый хеш не соответствует требованию PoW (не начинается с нужного числа нулей).
- Демонстрируется, что для подделки блока злоумышленнику потребуется заново выполнить майнинг (что вычислительно затратно).
